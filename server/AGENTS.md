# server/

Bun backend: HTTP API + WebSocket fan-out over herdr's unix-socket API, plus the PTY attach sidecar. The attachment lifecycle and transport quirks live here and nowhere else.

## ANTI-PATTERNS
- Never let an attachment outlive its last client. Cleanup paths: `detach`/`close` for members (`detach()` closes on an empty client set), `releaseUnclaimed` for an attach cancelled mid-creation, `onExit` for a pty that died, `stop()` for everything.
- Never `attachments.set` outside `spawnAttachment`, and never await between that `set` and `new PtySession(...)`: the record's `pty` is a placeholder until then.
- Never add the client to `attachment.clients` before checking `client.data.attached` still holds the same claim after the await. Detach followed by reattach installs a new claim.
- Always resize the pty from the geometry of an INTERACT client's attach (`attach` handler calls `resizePty` when `mode === "interact"`); an observe attach never resizes, and a mirrored pane keeps the pane's own grid (`pane-geometry` with `fixed: true`). Never spawn `herdr terminal attach` without cols/rows.
- Answer in-band: handler failures are sent as `{type:"error"}` frames. The only deliberate closes are 4008 (output stall/overflow), 1008 (device revoked) and 1012 (relay/PC gone).
- Keep `herdr/` free of HTTP concepts — it speaks only herdr's socket protocol; HTTP shaping belongs in index.ts.
- NEVER refresh an OAuth token in usage.ts. Claude, Codex, Cursor and Grok rotate refresh tokens, so a refresh their CLI did not make signs that CLI out; an expired sign-in is reported as `expired` and left for the CLI to renew. Nothing is read in the background, and a provider that answered 429 is not asked again before it said to.
- From the first paired device on, the gate is closed to strangers and stays closed when every device is revoked — revoking must never reopen the LAN — while this PC itself gets in without pairing (once a token is set, every client needs it, except a paired device, whose cookie is accepted before the token is asked for). A devices.json that will not parse is not a first installation: keep it for recovery and let the local/token/Tailscale routes serve the owner.
- Only proof says a herdr is gone (herdr-marker.ts): a refused connection, or on Windows a marker whose pid is gone, is not herdr, or started at another time. A slow daemon, an unreadable marker or an unreadable process table is never "stale": on Windows herdr.sock is a `pid:start` marker file a killed daemon leaves behind, and the pid alone says nothing, because Windows hands a dead process's pid to the next one.
- The user's own API keys (voice.ts, usage.ts) are read on the server and sent upstream only: no answer or error message carries one. voice.ts scrubs the key out of a provider's failure text; usage.ts answers with problem codes and drops a failed answer's body, but logs an exception's message as it is, so never put a credential into an error thrown there.
- Cache-Control is decided per file in static.ts: only Vite's fingerprinted `/assets/` may be pinned for a year. `sw.js`, the web manifest and the shell served for `/` and unknown paths must revalidate on every load (a direct `/index.html` request gets the one-day default), or the installed PWA is pinned to a build the user can no longer get rid of.

## CONVENTIONS
- `attachments: Map<paneId, PaneAttachment>` holds `{ pty, clients, cols, rows, replay }`. `cols`/`rows` are the pty's current grid: `resizePty` updates them and broadcasts `pane-geometry` to the pane's clients whenever they change. `replay` is a bounded 256KB tail sent to clients that attach late; `pty-exit` broadcasts first, then closes the attachment.
- Read-only live views (`watch.ts`, herdr >= 0.7.2) run `herdr terminal session observe <pane_id> --cols C --rows R` with plain `Bun.spawn`, never the PTY sidecar. A writable attach locks the pane at the browser's size; the observer does not take resize ownership (measured on 0.9.3: the TUI pane stayed 44x37 while observed at 150x50), so a tab out of use detaches before watching.
- `SocketData.watches` owns one observer per pane and connection, independent of attachments, claims, ACK windows and pane geometry. Repeat watch replaces it; unwatch kills it silently; natural close/exit sends `watch-end` only for the current observer. Kill and clear watches on connection close, device revocation, stalled-consumer cleanup and `stop()`; read-only devices and observe-role connections may watch.
- `createServer` starts `startStatusCollector` (collector.ts): per-pane `agent_status_changed` for EVERY pane in the snapshot plus a global pane.created/pane.closed/pane.exited subscription. Every stream reopens itself when herdr closes it (events_lost, restart) with 250 ms→5 s backoff; a lifecycle stream that comes back reconciles, and a lost status stream resyncs from a snapshot taken after the new subscription started. Its callbacks `broadcastAll` `pane-status` / `pane-exited` / `session-changed` to every connected client — `pane-status` no longer depends on attachment. The client set is tracked in a `clients` Set (open/close).
- Sidecar protocol (pty-host.mjs): argv `<cols> <rows> <command> [args...]`; stdin newline-JSON frames — `{"t":"i","d":"<text>"}` writes, `{"t":"r","c":cols,"r":rows}` resizes; stdout is raw pty bytes unmodified; exit mirrors the child's code; sidecar clamps cols/rows to 1..1000.
- Output control adds `{"t":"p","paused":true|false}`. Parent pause and stdout backpressure are independent; both must clear to resume. Kill resumes the reader to observe EOF and has a bounded forced cleanup. PtySession awaits stdout EOF before reporting process exit.
- ACK-capable attaches carry `flow_control:"ack"`; `pty-data.flow` identifies the subscription and cumulative UTF-8 byte offset. `pty-ack` releases only already-sent credit in that subscription. Pause at 256 KiB, resume at <=64 KiB, close consumers blocked for 2s with code 4008; 1 MiB hard application/transport budgets. `-1` from Bun send is already queued, never retransmit it. Legacy clients have the transport cap only. See docs/terminal-flow-control.md and server/output.contract.test.ts.
- `HerdrError.code` → HTTP status (http.ts `errorResponse`): `connect_failed`/`timeout` → 502; other HerdrError codes → 404; anything else → 500 `internal_error`.
- Auth: auth.ts `isAuthenticated` accepts the `herdr_web_token` cookie or an Authorization Bearer (length-safe compare); access.ts `decideAccess` (token → device cookie → Tailscale owner, by login header, or with no login header on a tailnet one login provably owns when HERDR_WEB_TAILSCALE_SERVE_ONLY declares serve the only ingress → loopback local → pairing) runs for /ws and every /api/* route except /api/health, /api/auth and /api/devices/pair; static files stay open.
- An unauthenticated /ws upgrade is refused with a plain-text 401 `unauthorized` (the WS client never parses a body); every other refusal is the JSON envelope.
- `terminalInfoFor` resolves pane_id → `{ terminalId, rect }` from one fresh `session.snapshot` (rect = the pane's `layouts[].panes[].rect`, null when absent); missing pane → `pane_not_found`, pane without terminal → `no_terminal`.
- The layout `rect` is NOT the terminal's current size (measured on herdr 0.9.3): it stayed 120x40 while a `terminal attach` sized the pane 100x30, then 140x40, and the pane kept 140x40 after that attach left. Only the attached client's size is real; nothing in the API tells another bridge's size. An attachment started again (held retry, live handoff) therefore reuses its own cached `cols`/`rows` (#363 review). While a `terminal attach` is connected herdr holds the pane at that attach's size, and its own TUI cannot resize it; the TUI gets its own size back only when the attach ends (measured on 0.9.3 with a TUI client: a split pane 44x37, 150x50 while attached, 44x37 once the attach ended). The rect is not that size either: it includes the pane's border (a 47x39 rect was a 44x37 pty).
- Attachment creation: `ensureAttachment` returns the existing record, else joins the in-flight creation in `pendingAttachments` (cleared in `finally`), else starts `spawnAttachment`. An observe-first creation spawns at the pane's rect (fallback 80x24), never the observer's grid; an interact-first one at the client's grid. A mirrored pane always takes the pane's rect.
- The `attach` handler records the pane in `client.data.attached` BEFORE awaiting the creation, so a `detach` (the client's pane switch sends detach-old then attach-new) or `close` landing mid-creation cancels it; on resume a cancelled attach calls `releaseUnclaimed`, which closes the record only if it has no clients AND no other client still has the pane in `attached` (a joiner of the same creation that has not resumed yet). A failed creation removes the pane from `attached` again.
- `closeAttachment` removes the pane from every member's `attached`: after a pty exit the members sit on "terminal ended" and a stale entry would read as a live claim in `releaseUnclaimed`.
- An attach exit (not a read race, `attach_held` or a retired refusal) is not yet the pane's end: `ended` looks the pane up every 100 ms for `ATTACH_RELOOKUP_FOR_MS` (5 s). A new `terminal_id` (herdr live handoff) starts a new attach for the same clients; a gone pane gets `pty-exit` at once; the same terminal or an unreachable herdr gets it at the deadline. The timer is `attachment.relookup`, cleared in `closeAttachment` (#370).
- SocketData holds `attached`, `mode`, per-pane `output` windows and a `closing` flag. An observe connection's `input`/`keys`/`resize` answer `{type:"error", code:"read_only"}`, and its `attach` never resizes the pty — it receives the current `pane-geometry` and adopts it. Observers can acknowledge output.
- WS `keys` messages go through herdr RPC (`pane.send_keys`), not the pty; `input` goes straight into the pty, or to `pane.send_text` on a mirrored pane. A key for an attached pane waits `KEY_SETTLE_MS` after the pane's last pty keystroke, and `TYPED_SETTLE_MS` when that keystroke ended in an ESC (herdr holds a lone ESC on the pty ~150ms), so it never overtakes typing; typing that arrives while a key waits queues behind it.
- `SocketData.attached` maps pane IDs to opaque claims that last until detach or terminal end; repeated attaches preserve the current claim. Queued terminal `keys` retain that sender claim, attachment and pty. Recheck their identity, sender membership and readiness before sending, so detach (even followed by reattach) or terminal replacement cancels stale chords. A cancelled chord or text is answered `input_failed`, never `input_not_ready`: the client drops the pane's readiness on that code, and the attach it holds by now was already told `input-ready`. Unattached RPC keys keep their existing path.
- Pending chat messages are bridge-owned input intents, never native Tab copies. `pending-input.ts` gives automatic delivery and an explicit Send now action the same ID claim; only the originating live interact connection and pane lease can deliver it. Status comes through the existing collector and CompletionTracker. A committing key is not a new-turn receipt: further automatic sends require a later working/ready cycle. Unknown delivery outcomes never retry. Its checks read `source: "detection"` (a scrolled viewport hides a new menu) and refuse on `modelListWaits`; before the paste, a Claude input box that is not known to be empty (`claudeInputDraft`: typed text, bash mode, a clipped box; the box comes from the detection read, and the viewport's ANSI read, the only one herdr colors, tells grey from typed only when it shows the same box) refuses with `input_draft` and the message is held, never retried; a status read from a snapshot goes in through `mark`/`observe`, so it never overwrites a newer collector event.
- Malformed client frames get `{type:"error", code:"invalid_json"}` back; the connection is never dropped for a bad frame.
- Malformed roles (`role` with anything but interact/observe) and impossible geometry (non-integer or outside 1..1000 cols/rows) answer `invalid_role` / `invalid_geometry` error frames.
- On `open` every client immediately receives `snapshot`; if that herdr call fails it gets an `error` frame carrying the herdr code or `snapshot_failed`.
- `createServer({ port: 0, stateDir })` boots on an ephemeral port (how the contract tests run it, always with a temp stateDir); `stop()` closes every attachment before `server.stop(true)`.
- Push state (push.ts): VAPID keys load-or-generate lazily on first need; subscriptions keyed by endpoint, persisted via temp+rename 0600; 404/410 → delete + persist, other failures → log + keep. `seed(panes)` replaces titles and only FILLS missing status baselines (an event is newer than any snapshot). Payload = shared/protocol.ts `PushPayload`; TTL 12h; urgency high for blocked.
- The collector calls `onBaseline(snapshot.panes)` on EVERY reconcile (before the same-set early return): without it the first status event after a restart has no baseline and is dropped as a first sighting.
- A pane on a herdr without `terminal attach` gets a `MirrorSession` (mirror.ts) where a `PtySession` would stand, so the attach lifecycle, the late-joiner replay and the output window are unchanged. It reads the visible screen a few times a second and sends the rows that changed in ordinary `pty-data` frames, with the whole screen at the start, after a resize, every few seconds and once the screen goes quiet (whole screens were 135 KB/s against 9 KB/s for changed rows, #261). A repaint carries no cursor position, misses what happened between two reads, and its grid is the pane's own, never the browser's.
- Typing into a mirrored pane goes to `pane.send_text` (mirror-input.ts), and only a pane herdr names an agent on gets bracketed-paste markers around a pasted block: cmd and PowerShell do not read VT input, while a program that does read it receives the markers whether or not it turned paste mode on (#257, #269).
- omo and gjc are not kinds `agent.start` accepts (shell-agent.ts): the pane's shell runs the absolute path `/api/agents` discovered, and the pane's process tree — not its prompt — says when the agent is up. On Windows the shell is PowerShell or cmd, a newline in sent text is a line break in its editor rather than a run, and `process_info` names only the shell, so the shell's children answer instead.
- Queue-delivery submit IDs (`delivery: "queue"`) are idempotency receipts (pending-requests.ts): the same ID with another fingerprint is `invalid_submit_id`, and one already evicted from the bounded book is `retired_submit_id`. Never let either run a second time. An immediate submit keeps no receipt: sent twice, it runs twice.

## REMOTE BRIDGES
- Machine proxy forwards only allowlisted pane/workspace routes and its own bridge bearer credential. Never forward browser cookies/Authorization or remote Set-Cookie.
- SSH askpass secrets are in memory through private Unix sockets; persistent private keys and registries are 0600. Host-key changes fail closed.
- Remote process replacement requires explicit setup update approval, authenticated bridge/PID verification and managed_remote ownership. Never stop herdr itself or an independent bridge.
- Bundled runtime releases are immutable checksum-addressed directories. MachineRelay carries ACKs unchanged; never acknowledge remote output before the browser has parsed it.
